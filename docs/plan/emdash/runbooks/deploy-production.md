## CUT-1: go live on growgen.xyz (OWNER; agent-prepared in GON-183, owner checklist GON-214)

`growgen.xyz` is the **only** public hostname: no `www`, and `next.growgen.xyz` is retired afterwards with no redirect (owner decision 2026-11-26, D11). The `wrangler.jsonc` route is `growgen.xyz`, and `web-deploy.yml` builds with `EMDASH_SITE_URL=https://growgen.xyz`, so canonical, `og:url`, sitemap, RSS, the `robots.txt` `Sitemap:` line and JSON-LD all derive from that one origin (`astro.config.mjs` `site`). `scripts/cutover/cutover.test.ts` pins both.

Tools (all in `apps/web/scripts/cutover/`, all read-only against production):

- `preflight.mjs` (before the switch): `node apps/web/scripts/cutover/preflight.mjs --url <origin growgen-web serves today> --build`. Needs `CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE` set to the production **session pooler** string (export it from your shell; never paste it into a file or chat), an authenticated `gh`, and optionally `CLOUDFLARE_API_TOKEN` with Workers Builds read. It checks: config (route, `EMDASH_SITE_URL`, `PUBLIC_SITE_LIVE` default false), EmDash `site:staging` is off (READ ONLY SQL), the `PUBLIC_MIXPANEL_*` / `PUBLIC_ADSENSE_*` variables are set and `PUBLIC_SITE_LIVE` is not yet `true`, `ads.txt` is served, the deployed site is still noindex and `/_emdash/admin` is 404, a `PUBLIC_SITE_LIVE=true` build into `dist-preflight/` (with `DERIVE_READONLY=1`) passes `post-build` and names only `growgen.xyz`, and the legacy `growgen` Worker's auto-build is paused. A `MANUAL` line means the script could not verify it: do it by hand. Exit 0 means no failures.
- `smoke.mjs` (after the switch): `node apps/web/scripts/cutover/smoke.mjs` (default origin `https://growgen.xyz`; `--parity sample` for a quick run, `--parity off` to skip). It checks `/` is 200 with no `noindex` (header or meta) and the canonical on `growgen.xyz`, `robots.txt` allows crawling and lists `https://growgen.xyz/sitemap-index.xml`, every sitemap URL is on the origin, `/_emdash/admin`, `/_emdash/api/setup` and `/.well-known/oauth-authorization-server` are 404, `ads.txt`, `rss.xml`, `/about/`, `/podcast/`, `/world/`, `/tags/`, `/lab/` and a post (all indexable with the right canonical), `/umap/` and `/hero-gallery/` (200; they are `noindex` by design, so the `/umap/` line in GON-214 step 6 is a 200 check, not an indexing check), and that every path in `tests/legacy-urls.txt` (about 4,900, static assets) answers 200.

Run steps 3 to 5 in one sitting. After the PR is merged, `master` declares the `growgen.xyz` route, so any `web-deploy` (the nightly 02:17 UTC run, or a CMS publish) tries to attach it to `growgen-web`. While the legacy `growgen` Worker still holds the domain that deploy fails at the attach step (a red run, the previous deployment keeps serving). If you must stop between steps 3 and 5, revert the route first (see the step 3 rollback).

Ordered steps. **Rollback** says how to undo that step; the full rollback is the last section.

1. **Analytics and ads variables (GON-213/GON-214 step 1).** Set `PUBLIC_MIXPANEL_TOKEN`, `PUBLIC_MIXPANEL_API_HOST`, `PUBLIC_ADSENSE_ENABLED`, `PUBLIC_ADSENSE_CONSENT_READY`, `PUBLIC_ADSENSE_SLOT_ID` with `gh variable set <NAME> --env production --body "<value>"`. They stay inert until step 4. *Rollback:* `gh variable delete <NAME> --env production`. Nothing is public yet, so there is nothing to undo on the site.
2. **EmDash staging off, then preflight (step 2).** In the Docker admin, Settings, turn off "staging" (`site:staging`; while on, `<EmDashHead>` adds `noindex, nofollow` to every page, and a build with `PUBLIC_SITE_LIVE=true` fails in `post-build`). Confirm the legacy `growgen` Worker's Git auto-build is paused (Dashboard, Workers & Pages, `growgen`, Settings, Builds): the merge in step 3 must not trigger it. Check the `growgen.xyz` zone DNS (Dashboard, DNS, Records) for stray apex A/AAAA/CNAME records that are not managed by the legacy Worker's custom domain; an externally managed record makes the attach in step 5 fail. The `CLOUDFLARE_API_TOKEN` in the GitHub `production` environment already attached the soak host's custom domain, so it has the zone permission. Run `preflight.mjs --build` **from the GON-183 branch** (its config check needs the PR's `routes`; after the merge, from `master`). Export `CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE` as the `growgen_ci_readonly` session-pooler URL (runbooks/ci.md) so the database itself refuses writes, including from the EmDash prerender connection. Do not continue until it prints `0 failed` and you have done every `MANUAL` line. *Rollback:* turn "staging" back on in Settings (the site is not live yet, so this is cosmetic).
3. **Site URL secret, then merge the config PR (step 3).** In `apps/web`: `pnpm exec wrangler secret put EMDASH_SITE_URL -c wrangler.jsonc`, enter `https://growgen.xyz`. Then merge the GON-183 PR (it changes `routes` to `growgen.xyz`; nothing deploys on merge). *Rollback:* open a revert PR for the GON-183 merge (this puts the soak route back, so a later `web-deploy` cannot collide with the legacy Worker) and put the previous secret value back with the same command.
4. **Go-live flag (step 4).** `gh variable set PUBLIC_SITE_LIVE --env production --body "true"`. Exactly the lowercase string `true`; anything else stays not live (`src/lib/site-live.ts`). Nothing changes on the internet until step 5 deploys. *Rollback:* `gh variable set PUBLIC_SITE_LIVE --env production --body "false"`; re-running `web-deploy` is only needed if step 5 already deployed.
5. **Switch the domain (step 5).** Cloudflare Dashboard, Workers & Pages, legacy `growgen` Worker, Settings, Domains and Routes: detach `growgen.xyz`. **Leave that Worker deployed.** Immediately run `gh workflow run web-deploy.yml -f environment=production` and watch it to green; the `routes` entry makes `growgen-web` claim `growgen.xyz` (wrangler also creates the DNS record). **Gap:** between the detach and the end of the deploy (build, guards, upload; watch the run) `growgen.xyz` serves nothing, so choose a quiet moment. *Rollback* (do the numbered steps in this order): (1) merge a revert PR for the GON-183 route change, so no deploy can try to claim the domain again; (2) detach `growgen.xyz` from `growgen-web` (Dashboard, `growgen-web`, Settings, Domains and Routes) and re-attach it to the legacy `growgen` Worker; (3) set `PUBLIC_SITE_LIVE=false` (step 4 rollback) and re-run `web-deploy` so any remaining `growgen-web` host goes back to noindex; (4) if the soak host is still attached and you do not need it, detach it too.
6. **Smoke test (step 6).** `node apps/web/scripts/cutover/smoke.mjs`. Then by hand: search, the Mixpanel consent opt-in and opt-out, a few posts, and `pnpm exec wrangler tail -c wrangler.jsonc` in `apps/web` for CPU on a cold request. On any failure, roll back first, investigate after. *Rollback:* the step 5 rollback.
7. **Retire the soak host (step 7).** Only after step 6 passes. Dashboard, `growgen-web`, Settings, Domains and Routes: if `next.growgen.xyz` is still listed, detach it (the deploy in step 5 may already have dropped it, because wrangler treats `routes` as the Worker's route list; look, do not assume). Then delete its DNS record (DNS, Records) in the `growgen.xyz` zone if one is left. It was always noindex, so search has nothing to lose, and there is no redirect. *Rollback:* re-add the custom domain `next.growgen.xyz` to `growgen-web` in the Dashboard (re-creates the DNS record). It would serve the live, indexable build, so only do this to debug and detach it again.
8. **Search and ads (step 8).** Google Search Console: verify `growgen.xyz` and submit `https://growgen.xyz/sitemap-index.xml`. AdSense: confirm `growgen.xyz` is still listed and `https://growgen.xyz/ads.txt` resolves. *Rollback:* none needed (read-only submissions).
9. **Record the cutover.** Write the date and time in GON-214. CUT-2 (GON-184) follows the same day. After GON-215 deletes the legacy `growgen` Worker, the rollback above no longer works, so do not run GON-215 until you are sure.

### Full rollback (any time before GON-215)
1. Merge a revert PR for the GON-183 route change. Then detach `growgen.xyz` from `growgen-web` and attach it to the legacy `growgen` Worker. Its last deployment is untouched.
2. `gh variable set PUBLIC_SITE_LIVE --env production --body "false"`, then `gh workflow run web-deploy.yml -f environment=production` (any remaining `growgen-web` host returns to noindex; with the route reverted the deploy cannot collide). Put the `EMDASH_SITE_URL` secret back to the soak origin if you keep that host.
3. Re-check with `curl -sI https://growgen.xyz/` (the legacy site answers).

Build and deploy by hand (not the normal path): `pnpm --filter web build` (add `PUBLIC_SITE_LIVE=true` and `EMDASH_SITE_URL=https://growgen.xyz` only at CUT-1) then `pnpm --filter web exec wrangler deploy -c dist/server/wrangler.json` (`pnpm --filter web run deploy` does both; `run` is required, bare `deploy` is pnpm's built-in). `build` runs `scripts/check-static-routes.mjs` first (fails if any `src/pages` route lacks `prerender = true`).
