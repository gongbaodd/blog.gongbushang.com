# Scout note S0-4: storing a raw Markdown body in EmDash

Checked 2026-11-24. Sources: npm `emdash` 1.6.0 (dist types, `reference/field-types` doc), npm `@emdash-cms/plugin-field-kit` 0.1.4 (package and `plugins/field-kit` doc), and the `portable-text` module in `emdash` dist.

**Verdict:** Use the core `text` field type. No Markdown or code field type exists in core or Field Kit. The admin shows a plain multi-line textarea, with no preview and no syntax highlighting.

## Need
Store each post body as a raw Markdown string (D5). Editors must be able to edit it in the admin, and the build reads it back unchanged.

## Use
- **Core `text` field**: "Multi-line plain text". It maps to a `TEXT` column. The widget is a textarea with a `rows` option (default 10). Validation options are `minLength`, `maxLength`, and `pattern`; none is set by default. Field types doc, "text" section.
- Schema snippet:
```ts
{ slug: "body_md", label: "Body (Markdown)", type: "text", required: true, options: { rows: 40 } }
```
- Optional `select` field (`body_format`, value `markdown`) for a future format switch.
- Admin editor: plain textarea. A preview or a Markdown toolbar would need a custom field widget in a native plugin. The Field Kit doc says to write your own widget if Field Kit doesn't fit. Not tested.
- Spike check (S0-4): round-trip a post containing KaTeX, a Mermaid fence, and a PlantUML fence through the REST API and the admin, byte for byte. Watch for escaping or CRLF changes.

## Considered and rejected
- **`portableText`**: the write path converts a Markdown string to Portable Text (`convertDataForWrite` → `markdownToPortableText`, marked lexer, GFM). The read path converts back to Markdown. It's lossy for our custom syntax (attributes, KaTeX, Mermaid/PlantUML fences; not tested) and it's BL-PT's job. Rejected for D5.
- **`json` + Field Kit**: Field Kit widgets (`object-form`, `list`, `grid`, `tags`) only attach to `json` fields. They have no text or code editor. Rejected.
- **`repeater` / `blocks`**: no Markdown editor, and no nesting of a raw text field inside a complex field. Rejected.
- **`code` type**: does not exist as a field type. The string "type: code" appears only in Portable Text code blocks.
- **Third-party Markdown field plugin**: `npm search emdash markdown` returns only unrelated packages (registry-client, auth, smtp, and similar). None fits.

## Free-tier impact
None. A post body is a few KB to a few MB of TEXT in Supabase's 500 MB DB (§10). Images stay on Cloudinary.
