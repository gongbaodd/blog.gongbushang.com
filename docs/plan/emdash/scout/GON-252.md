# Scout: GON-252 Sign in with Google (apps/admin)

Checked 2026-11-28 against `emdash@1.6.0` (npm, modified 2026-11-22), the copy in `apps/admin/node_modules`, and https://docs.emdashcms.com/guides/authentication/.

**Need**: Google sign-in on the Docker admin, only for `ADMIN_ALLOWED_EMAILS` with verified email, producing the normal EmDash session, next to passkeys.

**Use**: EmDash 1.6.0 built-in Google provider, plus a small allowlist gate in `apps/admin/src/outer.ts`. No new dependency.

```js
// apps/admin/astro.config.mjs (inside emdash({...}))
import { google } from "emdash/auth/providers/google";
authProviders: [google()],
```

Env names EmDash reads (runtime `process.env`; prefixed name checked first):
- `EMDASH_OAUTH_GOOGLE_CLIENT_ID` / `EMDASH_OAUTH_GOOGLE_CLIENT_SECRET` (or `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`)
- The ticket's `GOOGLE_OAUTH_CLIENT_ID` / `_SECRET` are NOT read by EmDash. Use the names above, or the ticket is not met.
- `ADMIN_ALLOWED_EMAILS` (ours, new): comma-separated, compared lowercase. Unset means deny all Google sign-ins.

### Q1: what EmDash 1.6.0 already ships
- Provider: `dist/auth/providers/google.mjs`. Login button: `src/auth/providers/google-admin.tsx`, shown only when listed in `authProviders`.
- Routes: `/_emdash/api/auth/oauth/google` (start) and `.../google/callback`, injected by `injectBuiltinAuthRoutes` in `dist/astro/index.mjs`.
- Already enforced: PKCE (S256), random state stored in `auth_challenges` (10 min TTL), userinfo with the access token, and `email_verified` must be true to link an existing user (`@emdash-cms/auth` `findOrCreateOAuthUser`).
- Missing: no email allowlist. Any verified Google account matching an existing user row logs in. New users self-sign up if setup is incomplete or an enabled `allowed_domains` row matches (callback `canSelfSignup`).
- Session: callback calls `startUserSession` (sets `session.set("user", {id})`, updates `last_login_at`). It is not in the package exports. The docs describe no public API for custom session creation, so do not rely on `emdash/src/auth/*`.

### Redirect URIs (exact origin of `EMDASH_SITE_URL`, which `getPublicOrigin` reads first)
- local: `http://localhost:4322/_emdash/api/auth/oauth/google/callback`
- production: `https://admin.growgen.xyz/_emdash/api/auth/oauth/google/callback` (hostname from `.env.example`; Lead to confirm)

### Implementation outline
1. `apps/admin/astro.config.mjs`: add `authProviders: [google()]`. Keep passkey mode. Do NOT set the `auth` option (see rejected).
2. `apps/admin/src/google-allowlist.ts` (new): `parseAllowlist(env)` and `isAllowed(email, env)`. Empty list denies everything.
3. `apps/admin/src/outer.ts`: only for `GET /_emdash/api/auth/oauth/google/callback`, call `await next()`, then read `session.get("user")?.id`. Look up `users.email` via `locals.emdash.db` (populated after `next()`). If not allowed: `session.destroy()` and redirect to `/_emdash/admin/login?error=oauth_denied&message=...`. The email is only known after the token exchange, so this is a post-check. Keep Access check first.
4. `apps/admin/.env.example`: add the three names with placeholders only.
5. `apps/admin/docker-compose.yml`: pass them as runtime env, never build args. `check:secrets` stays green (use `process.env`, not `import.meta.env`).
6. Tests: `google-allowlist.test.ts`; extend the outer test with the callback deny path (fake session and db).
7. Runbook: Google client setup steps in `docs/plan/emdash/runbooks/admin-docker.md`.
8. Ops check before go-live (read-only SQL): `allowed_domains` has no enabled rows and `emdash:setup_complete` is true. Otherwise a stranger can self-sign up as admin.

Smoke test: `http://localhost:4322` and the production host. The callback goes through the Access gate on the same host; the browser sends `CF_Authorization` on the redirect, so verify it works.

### Considered and rejected
- Cloudflare Access with Google as IdP (option 3): no app code, but it only gates the edge. EmDash still needs its own session, so passkeys remain the only way in. Keep Access as the outer gate and its email policy as a second check.
- EmDash `auth` option = Cloudflare Access (external mode): docs say that disables passkeys and providers in production. Rejected.
- Custom arctic/oslo + jose: works, but duplicates PKCE, state and email-verification logic, and EmDash's login page only renders buttons from `authProviders`, so it needs UI work too. More risk for no gain.
- Magic link: needs an email provider; not asked for.
- Google OAuth consent: openid/email/profile are non-sensitive scopes. Publish to Production rather than leaving it in Testing (Testing caps users and token lifetime). Skip the logo to avoid brand verification.

### Free-tier impact
None. Google OAuth is free. The admin is Docker, so no Workers CPU. One extra SELECT on callback. Cloudflare Access unchanged.
