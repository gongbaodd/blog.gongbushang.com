# Scout note S0-6: publish → rebuild trigger

Checked 2026-11-24. Sources: docs.emdashcms.com (reference/hooks, reference/content-lifecycle, plugins/creating-native-plugins/your-first-native-plugin, plugins/creating-plugins/capabilities), `emdash` 1.6.0 dist, `@emdash-cms/plugin-webhook-notifier` 0.2.4 (npm package), GitHub REST docs for repository dispatch, and this repo's `.github/workflows/sync-content.yml`.

**Verdict:** Use a small native plugin with the `content:afterPublish` hook, calling `repository_dispatch` with a fixed token. Don't use `@emdash-cms/plugin-webhook-notifier` as is. EmDash has no core webhook feature.

## Need
When an entry is published (including scheduled publishes), dispatch a GitHub `repository_dispatch` so `sync-content.yml`-style workflow rebuilds and deploys the static site (D9).

## Use
- **Hook**: `content:afterPublish` runs after the publish response and covers scheduled publishes. It needs the `content:read` capability. Errors are logged and don't undo the publish. Our cron trigger (`* * * * *` in the template) already drives scheduled publishing.
- **Native plugin** (runs in the Worker process, so it can call `fetch()` directly): `definePlugin` with `capabilities: ["content:read"]` and `hooks: { "content:afterPublish": ... }`. Register it in `emdash({ plugins: [...] })`. The native loader requires a named `createPlugin` export. Native plugins can read secrets from `process.env`, and on Workers `wrangler secret put` reaches `process.env` with `nodejs_compat` and a compatibility date of 2025-04-01 or later.
```ts
// packages/emdash-deploy-hook (sketch)
export function createPlugin() {
  return definePlugin({
    id: "plugin-deploy-hook", version: "0.1.0", capabilities: ["content:read"],
    hooks: {
      "content:afterPublish": async (event) => {
        await fetch(`https://api.github.com/repos/${OWNER}/${REPO}/dispatches`, {
          method: "POST",
          headers: {
            Accept: "application/vnd.github+json",
            Authorization: `Bearer ${process.env.GITHUB_DISPATCH_TOKEN}`,
            "User-Agent": "emdash-deploy-hook",
          },
          body: JSON.stringify({ event_type: "content-published", client_payload: { collection: event.collection, id: event.content.id } }),
        });
      },
    },
  });
}
```
- **Token**: a fine-grained PAT with **Contents: write** on this repo only (classic PAT needs `repo`). Store it with `wrangler secret put GITHUB_DISPATCH_TOKEN`. Never in `astro.config` or the repo. Set an expiry and rotate it.
- **Dispatch API**: `event_type` is required (≤100 chars). `client_payload` ≤10 top-level keys and ≤64 KB. Responses: 204 success, 422 validation or "spammed". Debounce with a workflow `concurrency` group, as `sync-content.yml` already does, so a burst of publishes causes one build.
- **Workflow**: add `repository_dispatch: types: [content-published]` to a workflow. Keep the existing `schedule` cron in `sync-content.yml` as the nightly safety net (D9).

**Considered: `@emdash-cms/plugin-webhook-notifier` 0.2.4.** It posts to a user-set URL with `Authorization: Bearer <secret>`. But: (a) it hooks `content:afterSave`, so it fires on every draft save; (b) its JSON body has `event`, `timestamp`, `resourceId`, and no `event_type`, so GitHub returns 422; (c) it needs `network:request:unrestricted`. Only usable if we proxy through a Worker that rewrites the body. Not chosen.

**Fallback if the hook fails:** the nightly cron in `sync-content.yml`, plus `workflow_dispatch`. A manual "Publish" button in the admin can't trigger a build without the hook.

## Considered and rejected
- **Core webhook setting**: none found in the docs or dist.
- **Sandboxed plugin**: sandbox needs Workers Paid and D1, not Postgres (§10).
- **Cloudinary's own webhook**: unrelated to EmDash publish events.
- **GitHub App token**: works, but a PAT is simpler for one repo.

## Free-tier impact
- GitHub Actions: unlimited for public repos (§10). Debounce keeps build count down.
- Workers: one `fetch` per publish, well inside 100k requests/day and the 50-subrequest limit. The hook adds a few KB to the script (3 MB limit, §10).
- Admin on the local-only fallback (§10): `afterPublish` still runs in-process, so the dispatch still fires.
